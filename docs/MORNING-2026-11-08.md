## First, the phone needs you

At about 23:50 a boot-menu speed test (the hidden row `menubench`) froze, and the phone has been off USB since.
The test entry had `no_launch = true`. On such entries the loader never arms its watchdog, so nothing could

## What got done (before the hang, and on the Mac all night)

**Windows**
- **Wi-Fi works on open networks:** IP address from the router, internet, 0 of 48 pings lost, reconnects in about
  5 s. The fixes: Windows ignored the driver's "joined" message, and the driver read and wrote frames in the
  wrong format. Speed was 2–4 Mbit/s, but that open network caps it; the driver itself hit about 75 Mbit/s in
  bursts. W2p (staged) adds 256 send buffers and no more dropped packets.
- **Password networks (WPA2):** the whole handshake is tested on the Mac (467 checks), but needs your hotspot
  once. W2p is the build to test.
- **x64/x86 programs (Steam) work.** The cause was a zero timer frequency on this phone, which made Windows'
  emulator divide by zero. Fixed with one registry setting (`ScaleRdtsc=0`).
- **Starbite Link:** clicks and keys all arrive in Windows (0 failures in the log), and it reconnects after a
  sign-out.

**Big cores**
- Windows can't mix big and small cores: the small cores support instructions the big cores don't, and Windows
  picks its instruction set once, on the first core. So the plan is the **4 big cores only**.
- The hand-off to a big core works, and the big core now runs Windows' boot loader. Each step found the next
  wall:
  - the boot firmware's cleanup has to run on a small core;
  - the boot loader was set to small-core-only instructions (now patched);
  - Samsung's firmware gives the big core no core-management (PSCI) answers.
- Next on the phone, staged and checked:
  - **solo9:** Windows told there's no PSCI;
  - **solo10:** a small PSCI emulator patched into Windows;
  - then **3 big** and **4 big**.
  All can run unattended except 4 big, which needs you watching.

**Starbite OS (0.3 → 0.5.3, all staged, self-test images too)**
- New UI and emergency tile.
- Wi-Fi app: scan, join open networks, or any password network with the new on-screen keyboard. Radio
  interrupts save power.
- Settings saving (needs one store entry, T14).
- An emergency card you can fill in on the phone.
- A short Power press now always wakes the screen.
- CPU slows down while the screen is off.
- Boot time: 7.5 of the 12.5 s is the loader's full power-on self-test (your setting). The quick self-test
  would give a first screen in about 5 s; your call.

**Boot menu (nothing in BOOT changed)**

- Fixed labels cut off mid-word, gave One UI the right Android logo, gave Utility OS its own tile, and made

- Screens: `build/menu/screens/` (before/after, contact sheet). Details: `docs/BOOT-MENU-OVERNIGHT.md`.
- The new menu runs as a **trial** chain-load first; it only goes into BOOT with you present.

**One UI**
